# W2：大模型应用开发

> 目标：掌握模型调用和结构化交互。
> 验收：能解释从用户输入到工具执行、结果回传和最终回答的完整链路。

## 一句话核心

W2 其实只学一件事：**模型不直接回答，而是告诉你"要调用哪个工具、参数是什么"；
你的代码执行工具，把结果交回模型，模型再给出最终回答。**

这个循环是后面 Agent 的全部基础。其他四个知识点都是在给它做配套。

## 五个知识点（按依赖顺序，不要跳）

| # | 知识点 | 学完能做什么 | 验收 |
|---|---|---|---|
| 1 | 模型 API 调用 | 发一条消息，拿到回复 | 能说出请求体和响应体里每个字段的含义 |
| 2 | Prompt + 结构化输出 | 让模型输出 JSON，用 Pydantic 校验 | 模型乱输出时你能拦住并重试 |
| 3 | Tool Calling | 模型选择工具、你执行、结果回传 | 能画出完整的消息往返顺序 |
| 4 | SSE 流式输出 | 边生成边推给前端 | 能解释为什么不能先收集完再返回 |
| 5 | Token 与成本 | 从 `usage` 统计每次调用 | 能算出一次对话的大致成本 |

## Tool Calling 的循环（必须能背下来）

```
用户消息 + 工具列表(schema)
        ↓
      模型
        ↓
  ┌─ 返回 tool_calls ──→ 你的代码执行工具 ──→ 把结果作为 tool 消息追加
  │                                              ↓
  └──────────────── 再次调用模型 ←───────────────┘
        ↓
   返回普通文本（结束）
```

模型**从不执行任何东西**，它只是输出"我想调用 `query_task_status`，参数是 `{task_id: 1}`"。
执行永远是你的代码。

## 验收问题（第七天自问）

1. 模型返回 `tool_calls` 时，`content` 字段通常是空的，为什么？
2. 工具执行失败时，应该抛异常还是把错误信息作为工具结果回传？各有什么后果？
3. 一次请求里可能有多轮 tool calling，你用什么条件决定"停止循环"？
4. 流式输出和 tool calling 能同时用吗？会遇到什么问题？
5. 同一句话调用了两次模型，`usage` 应该怎么累加？

## 开始前

在 `project/.env` 里填：

```
APP_LLM_API_KEY=你的key
APP_LLM_BASE_URL=https://api.minimax.chat/v1
APP_LLM_MODEL=MiniMax-M3
APP_LLM_DISABLE_THINKING=true
```

MiniMax 实测结论：

- `MiniMax-M2` 已下线，当前可用 `MiniMax-M3`、`MiniMax-M3.1-Flash`、`MiniMax-M2.7` 等
- `MiniMax-M3.1-Flash` 强制开启思考，不能设 `thinking.type=disabled`
- `MiniMax-M3` 支持关闭思考，且支持 function calling
- 私有参数（如 `thinking`）必须通过 OpenAI SDK 的 `extra_body` 传，直接当关键字参数会报 `TypeError`

然后启动服务，在 `/docs` 里调 `POST /api/v1/assistant/chat`。
